# Billing

## Назначение
Коммерческий слой DDCRM.

## Что поддерживает Billing
- тарифы
- add-on
- подписки проекта
- платежи
- продления
- отключение add-on
- ручные платёжные сценарии
- автоматические сценарии через эквайринг
- возвраты

## Коммерческая модель
- один проект = отдельная подписка
- у одного пользователя может быть несколько платных проектов
- тарифы и add-on настраиваются в БД
- площадки могут входить в тариф и могут продаваться отдельно
- доступы включаются автоматически после оплаты

## Источник истины по оплате
- канонический источник состояния оплаты и подписки: **Billing**
- webhook эквайринга — входные события для Billing
- итоговый статус фиксируется после валидации события в Billing

## Политика обработки событий
- webhook обрабатываются с дедупликацией
- мутации Billing выполняются с `idempotency key`
- конфликтные кейсы закрываются reconciliation-процедурой

## Поддерживаемые сценарии
- новая подписка
- продление
- покупка add-on
- отключение add-on
- ручная активация
- возврат

## Trial и Grace
- значения `trial/grace` задаются политикой тарифа
- Billing передаёт в Entitlement параметры выбранного тарифа

## Что происходит при снижении функционала
Если проект утрачивает часть функционала:
- новые площадки, не входящие в entitlement, запрещаются
- уже существующие неразрешённые площадки блокируются, но не удаляются сразу
